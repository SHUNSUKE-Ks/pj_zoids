# 01 制作パイプラインの基本

## 方針：形の塊 → 骨 → 動き → 細部 の順
**動きが決まるまで、細部のメッシュは作らない。**
細部はあとから載せ替えられるが、関節の位置と部品の分け方は、動きを作ってからでないと正解が分からないため。

```
0 参考資料 ─ 1 プロキシ(部品の塊) ─ 2 リグ ─ 3 動き ─ 4 検査/評価 ─┬─ 5 形の作り込み ─ 6 引き渡し
                  ↑                                               │
                  └──────────── 形・関節が違えば戻る ─────────────┘
```

| 工程 | やること | 完了の条件 |
|---|---|---|
| 0 参考資料 | 真横・正面・上・斜め・関節の寄り。配色の基準を1枚決める | 4面が揃っている(足りなければ集め直す) |
| 1 プロキシ | 箱・円柱・凸包で**部品ごと**に塊を作る。1部品=1骨 | 真横と正面のシルエットが参考と重なる。関節の位置が決まっている |
| 2 リグ | 骨の親子、変形する骨/コントロール骨、IK、制約 | 静止姿勢で IK をかけても形が動かない(ずれ 0) |
| 3 動き | 歩容(足の順番とタイミング)、胴・首・尾の動き | 1周期がつながる(ループ) |
| 4 検査 | 自動検査(足滑り・めり込み・脚の伸びきり) + 目視(コマ割り・4面図) | 自動検査が全部 OK、目視で違和感の原因を言葉にできる |
| 5 作り込み | 部品の形、面取り、ホース、パネル | 骨・部品名・ピボットは変えない |
| 6 引き渡し | 外部AIやゲームエンジン向けに書き出す | 05 の条件を満たす |

## 環境
- Blender をヘッドレス(`blender -b`)で Python から動かす。すべてコードから再生成できる状態を保つ
- 実行: `tools/bl.ps1`。検査: `src/check_motion.py`。確認画像: `src/review_shots.py`(4面図)、`src/gait_sheet.py`(歩行のコマ割り)
- GUI は「確認と手直し」に使う。GUI で直した値は、コードへ書き戻す

## 学び(このプロジェクトで実際に起きたこと)
- **骨の姿勢の代入は、親の更新待ちで壊れる**。`pose_bone.matrix = M` は親が未評価だとずれる → 行列を自前で計算してポーズ値を入れる(`zoidkit/rig.py` の `Keyer`)
- **IK の Pole Angle は脚ごとに違う**。膝の曲がる向きが逆なら値も逆(狼: 前脚 -90°、後脚 +90°)。候補を試して自動で決める(`calibrate_pole_angle`)
- **検査の閾値が広いと誤検出する**。接地判定を「静止時の高さ+5mm」にしたら誤検出が消えた
- 形より先にディテールを足すと、プロポーションの修正で全部やり直しになる(Ver1.1 → Ver2.0 で経験)
