# Opus 評価依頼テンプレート

区切り（マイルストーン）ごとに、Opus へこの文書をそのまま渡して評価を頼む。
結果は `docs/review_v<版>.md` に残し、Sonnet への実装指示として使う。

### 撮影コマンド
```powershell
.\tools\bl.ps1 src\build_demo.py
.\tools\bl.ps1 -Blend out\demo.blend src\review_shots.py
magick montage out\review\*.png -tile 2x -geometry +2+2 out\review_sheet.png
.\tools\bl.ps1 -Blend out\demo.blend src\gait_sheet.py 8 1 2
magick montage out\sheet\*.png -tile 4x -geometry +2+2 out\gait_sheet.png
```

## 依頼文（ここから下をコピーして渡す）

> あなたは3Dメカのモデリングとリギングのレビュアーです。
> Blender 4.4 をヘッドレス(Python)で使い、ゾイド「コマンドウルフ(アーバイン仕様)」を作っています。
> 添付の参考画像と現状のレンダリングを比べ、次の3点を評価してください。
>
> **A. 現状の評価（参考画像との差）**
> - シルエット(真横・正面・上)、プロポーション(胴の長さ/高さ、脚の長さ/太さ、頭の大きさ/位置)
> - 部位ごとの形(頭部とキャノピー、胴体とバックパック、背部砲、四肢と関節、尾、装甲の配色)
> - 動き(歩行シート)がオオカミの駆け足に見えるか
> - それぞれ「差の大きさ」と「見た目への影響」で優先度 P1〜P3 を付ける
>
> **B. リグの構成見直し**
> - 今後やりたい動き：ギャロップ、横ステップ、走りながらの斜めステップ、歩容の切り替え、砲の旋回
> - 足りない骨、不要な骨、親子関係の見直し、GUIで手修正できる仕組み(コントロール骨・IK)の要否
>
> **C. Ver2.0 のメッシュ設計**
> - パーツ分割(どの骨にどの部品を付けるか)、ポリ数の目安、ディテールの段階(何を先に足すか)
> - 作り方の比較：①Opus が設計して Sonnet が Python で組む ②3D生成AI(Hunyuan3D)で形を出してパーツに切り分ける
>
> **出力形式**
> - 優先度付きの改善リスト(表)。各項目に「何を」「どの数値へ」「どのファイル/関数で」を書く
> - Sonnet がそのまま実装できる粒度の作業順
> - 判断に迷う点は、決め打ちせずに選択肢として挙げる
>
> **制約**
> - 動き(歩容・IK・ポーズ計算)は動いているので、作り直しではなく拡張で考える
> - 生成物はすべて Python から再生成できる状態を保つ(手作業の .blend 編集に依存しない)
