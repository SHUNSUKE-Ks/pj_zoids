# リグの入れ方ガイド（コマンドウルフを例に）

Claude Code に任せている部分の「中身」を、あとで自分で読み書きできるようにするための資料です。
コードは `src/zoidkit/`(種類に依存しない共通部品) と `src/species/command_wolf.py`(狼の数値と部品)。
設計判断と「なぜ」は `docs/knowledge/` にまとめています。

---

## 0. 全体像：3つの層

```
①モデル(メッシュ)  ← 見た目。箱・円柱・凸包を組み合わせたもの
        ↑ 頂点グループ + Armatureモディファイア で結びつく
②リグ(アーマチュア/ボーン) ← 骨。動かす“ハンドル”
        ↑ キーフレーム(位置・回転・拡大縮小)
③アニメーション ← 各フレームで骨をどう動かすか
```

- **メッシュ自体は動かさない。骨を動かして、メッシュが骨に付いていく**のがリグです。
- この案件では、メッシュ・骨・アニメの3つを全部 Python で生成しています（`make_model` / `make_rig` / `animate`）。

---

## 1. 骨(ボーン)の基本

| 用語 | 意味 |
|---|---|
| **Armature** | 骨のかたまり(オブジェクト)。ここでは `CommandWolf` |
| **Bone** | 1本の骨。head(根元)と tail(先端)を持つ。骨の向きが「ローカルY軸」 |
| **Rest pose(レストポーズ)** | 骨を作った時の基準姿勢。「何も動かしていない状態」 |
| **Pose(ポーズ)** | レストからの差分。**位置・回転・スケール**の3つが「ポーズ値」 |
| **Parent(親)** | 親が動くと子も付いてくる。肩→上腕→前腕のような連鎖 |

**大事な考え方**: ポーズ値は「レストからの変化量（親から見た相対値）」であって、世界座標ではありません。

### このプロジェクトの骨の親子関係

```
root
├ IK_FL / IK_FR / IK_RL / IK_RR   (足のIKターゲット。コントロール骨)
└ body (後半身/骨盤)
  ├ cannon (背部砲)
  ├ tail1 → tail2
  ├ POLE_RL / POLE_RR               (膝の向きを決めるポール。コントロール骨)
  ├ RL_thigh → RL_shin → RL_foot → RL_toe    (後脚)  + ダンパー骨
  ├ RR_thigh → RR_shin → RR_foot → RR_toe
  └ chest (前半身。背骨の曲げ用)
    ├ neck → head → jaw
    ├ POLE_FL / POLE_FR
    └ FL_shoulder → FL_thigh → FL_shin → FL_foot → FL_toe  (前脚。肩甲骨つき) + ダンパー骨
      FR_shoulder → FR_thigh → FR_shin → FR_foot → FR_toe
```

- **背骨を1本増やして `body` と `chest` に分けた**のがポイント。ギャロップで「背中が丸まる/伸びる」動きは、この2つの間の曲げで作っています。
- **変形する骨(Deform)** と **コントロール骨(Controls)** を分けています。GUI の骨コレクションで表示を切り替えられます。
- コード: `species/command_wolf.py` の `bone_defs()`、`zoidkit/rig.py` の `leg_bone_defs()`

### 組み合わせ方式（どの骨を誰が動かすか）
| 骨 | 動かすもの | GUIで手直し |
|---|---|---|
| body / chest / neck / head / jaw / tail / cannon / shoulder / toe | Python がキーを打つ | キーを直接編集 |
| IK_脚 | Python がキーを打つ(足首の位置と足の角度) | **掴んで動かせる** |
| thigh / shin | Blender の IK 制約が解く | IK_脚 を動かせば付いてくる |
| foot | IK_脚 の回転をコピー(Copy Rotation) | 同上 |
| ダンパー(_cyl / _rod) | 互いを向く(Damped Track) | 触らなくてよい |
| POLE_脚 | 胴に固定 | 動かすと膝の向きが変わる |

## 2. メッシュを骨に付ける(スキニング)

やり方は2通りあります。

| 方式 | 内容 | 使いどころ |
|---|---|---|
| **剛体スキニング(今回)** | パーツ丸ごと1本の骨に100%付ける | メカ・ロボット。関節で曲がる“皮”が無い |
| **ウェイトペイント** | 頂点ごとに複数の骨へ重みを付ける | 生き物の皮膚、布、なめらかな曲がり |

メカは剛体スキニングで十分です。関節は円柱(膝・足首)で隠せます。

### やっていること (`Parts.build`)
1. パーツのメッシュを作る（静止姿勢のワールド座標で）
2. **頂点グループ**を骨と同じ名前で作り、全頂点に重み 1.0 を入れる
3. **Armatureモディファイア**を付けて、対象を `CommandWolf` にする
4. メッシュを Armature の子にする

この「頂点グループ名 = 骨名」の一致が、Blender がメッシュと骨を結びつける唯一のルールです。

> GUIで確かめるには: `out/demo.blend` を開き、メッシュを選択 → データ(緑の三角)タブの「頂点グループ」を見る。

## 3. 脚のしくみ（今回の追加）

### 3-1. 関節構造
デジグレード(つま先立ち)の犬脚を、肩甲骨(前脚のみ)+3節+指で表現しています。

```
[肩甲骨] ─ 股関節(hip) ─大腿─ 膝 ─すね─ 足首(ankle) ─中足(foot)─ 指の付け根(ball) ─指(toe)─ 指先
                                                                 ↑ここが地面に着く接地点
```

- 前脚は膝が後ろへ、後脚は膝が前へ曲がる。これが「犬の脚」の見え方の決め手です (`LegSpec.bend` ±1)。
- **肩甲骨**: 前脚の付け根ごと前後に振って、踏み出しを伸ばします。
- **指**: 接地中は地面に平らに保ち、蹴り出しでは指の付け根を支点にかかとが上がります。

### 3-2. IK（逆運動学）
- **FK**: 関節の角度を決めて、先端の位置は結果として決まる。
- **IK**: 先端(足首)の位置を決めて、関節の角度を逆算する。

足は「地面のここに置きたい」が先にあるので IK が向いています。2リンク(大腿+すね)のIKは中学の幾何で解けます:

```
hip から ankle までの距離 d → 余弦定理で「膝までの前進量 a」と「膝の高さ h」を出す
膝 = hip + a×(ankle方向) + h×(膝を曲げたい向き)
```
- 脚は **Blender 標準の IK 制約**で解いています（すねの骨に IK、Chain Length 2、ターゲット `IK_脚`、ポール `POLE_脚`）。
- 自前の計算 `solve_knee()`（`zoidkit/leg.py`）は、静止姿勢の膝の位置と「脚が届くか」の検査に使っています。
- **Pole Angle の落とし穴**: 骨のローカルX軸とポールの向きのずれなので、膝の曲がる向きが逆の脚では値も逆になります（狼: 前脚 -90°、後脚 +90°）。`calibrate_pole_angle()` が候補を試して自動で決めます。

### 3-3. ダンパー（油圧シリンダー）
実機のダンパーは「筒とロッドが滑り合って伸び縮みする」もの。

- 筒(`_cyl`)とロッド(`_rod`)を**別の骨**にし、**Damped Track 制約で互いを向かせて**います。キーは不要です。
- 筒もロッドも伸縮させず、2つの重なりが変わることで長さが変わります（ゴムのように伸ばすより、メカらしく見える）。

コード: `DamperSpec`（`zoidkit/leg.py`）、`add_leg_constraints()`（`zoidkit/rig.py`）

## 4. 歩容（ゲイト）＝歩き方をデータで決める

歩き方は「各脚がいつ地面に着き、いつ離れるか」の**位相(タイミング)**で決まります。

- 周期を 0〜1 として、各脚に**位相のずれ**を与える (`Gait.phase`)
- 周期のうち `duty` の割合だけ接地し、残りは空中(遊脚)

### トロット（速歩）
対角の脚がペアで動く。左前+右後ろ → 右前+左後ろ。安定していて規則的。

```
位相   FL: 0.0   RR: 0.0   FR: 0.5   RL: 0.5      duty 0.5
```

### ギャロップ（駆け足）※オオカミ向け
4本の脚が**バラバラのタイミング**で着地し、全脚が浮く時間(浮遊期)がある。

```
着地順:  後脚 RR(0.0) → RL(0.10) → 前脚 FL(0.45) → FR(0.55)      duty 0.35
```
- 全部の脚が地面から離れる瞬間が2回ある(脚を集めた時と、伸ばしきった時)。
- **背骨が曲がる**: 脚を集める時は背が丸まり、伸ばす時は背が反る。これが「駆けている感」の一番大きな要素です。
- 胴体は**周期あたり2回上下**し、ピッチ(頭の上げ下げ)も付く。

コード: `species/command_wolf.py` の `GAITS`, `_gallop_motion()`、足の軌道は `zoidkit/gait.py` の `foot_pose()`

### 参考資料
- **マイブリッジの馬の連続写真**：ギャロップの位相が一目で分かる、定番の資料。
- **『The Animator's Survival Kit』(Richard Williams)**：四足歩行の章に、犬・馬・猫の歩容の図がある。

## 5. 足を地面で滑らせない

足が地面で滑ると一気に安っぽくなります。ここでは次のルールで防いでいます。

> **接地中、足は「胴体に対して」進行速度と同じ速さで後ろへ動く。**

- 本体(アーマチュアのオブジェクト)は一定速度で前進する。
- 足の位置は「本体から見た相対位置」で作る。接地中は本体の速度ぶんだけ後ろへ流す。
- → 世界から見ると、接地中の足は止まって見える。

`Gait.stride`（接地中に足が動く距離）は `速度 × duty × 周期の秒数`。速度を上げたいときは、
`stride` が脚の長さ(大腿+すね=1.7m)を超えないように、周期を短くするか duty を下げます。

## 6. 進行方向を変える（横ステップ・斜めステップ）

`Gait.dir` (x=右, y=前) を変えるだけで、**胴体は前を向いたまま**進行方向が変わります。

| dir | 動き |
|---|---|
| `(0, 1)` | 前進（既定） |
| `(1, 0)` | 右への横ステップ |
| `(-1, 0)` | 左への横ステップ |
| `(0.7, 0.7)` | 前方斜めに進みながらステップ |

```powershell
# 右への横ステップ（歩容はトロット）
.\tools\bl.ps1 src\build_demo.py -- 240 trot 1 0
# 前方斜めに走る
.\tools\bl.ps1 src\build_demo.py -- 240 gallop 0.7 0.7
```

- 仕組み: 足首の目標位置を、`dir` に沿って前後させるだけ (`zoidkit/gait.py` の `foot_pose`)。
- 本体の移動方向も `dir` に沿う (`animate`)。
- 横ステップ向けには、ギャロップよりトロット系の歩容を別に作る(足を交差させず、内側の脚を先に出す)のが自然です。`GAITS` に新しい歩容を1つ足せば、他は変えずに使えます。
- 走りながら急に斜めステップへ切り替える場合は、歩容をフレーム区間ごとに切り替え、`dir` を補間します（今後の課題）。

## 7. 「目標姿勢」から骨のポーズ値を出す数式

このプロジェクトで一番つまずきやすい所です。

Blender の骨は「親からの相対値」で動くので、「この骨をこの位置・向きにしたい(アーマチュア空間の行列 M)」から、ポーズ値を逆算する必要があります。

```
P_bone = P_parent × (rest_parent⁻¹ × rest_bone) × basis     ← ポーズ値(basis)を求めたい
basis  = (rest_parent⁻¹ × rest_bone)⁻¹ × P_parent⁻¹ × M
```

- `P_*` は「そのフレームの目標姿勢(アーマチュア空間)」、`rest_*` は静止姿勢。
- 得た `basis` を分解 (`decompose()`) して 位置・回転・スケール に入れる。
- コード: `zoidkit/rig.py` の `Keyer.key()`

> 最初は `pose_bone.matrix = M` と代入する簡単な方法を使いましたが、**親のポーズ行列がまだ更新されていない**ため、脚が外れる不具合になりました。
> 行列を自分で計算すれば、Blender の更新タイミングに左右されません（ヘッドレスで自動生成するときの定石）。

## 8. 自分で触って学ぶ（GUI）

1. `out/demo.blend` を Blender で開く
2. 3Dビューで `CommandWolf` を選ぶ → 左上のモードを **ポーズモード** にする
3. 足の骨(例 `FR_thigh`)を選び、`R`(回転)で動かして「ポーズ値」を体感する（`Alt+R` で戻す）
4. Outliner で骨の親子関係を見る
5. Dope Sheet / Graph Editor で、キーフレームがどんな波形になっているかを見る
   - 歩行はきれいなサイン波の重ね合わせ。ここが「歩容」の正体です。
6. `Ctrl+Z` で戻せるので、壊す心配はありません（生成物は `build_demo.py` で再作成できる）

## 10. 用語集
| 用語 | 意味 |
|---|---|
| Rig / リグ | 動かすための骨組みとその仕掛け全体 |
| FK / IK | 関節角から先端位置を決める / 先端位置から関節角を逆算する |
| Pole(ポール) | 2リンクIKで「膝をどっちへ曲げるか」を決める向き |
| Gait / 歩容 | 歩き方(足の着地順序とタイミング) |
| Duty(デューティ比) | 1周期のうち足が地面に着いている割合 |
| Stance / Swing | 接地している期間 / 空中で振り出している期間 |
| Skinning | メッシュを骨に結びつけること |
| Rest pose | 骨の基準姿勢 |
